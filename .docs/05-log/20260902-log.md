# Log 20260902

- **Sprint 13 Smart Capture from Image — implement โค้ดฝั่ง client + server เสร็จ:** สร้าง `api/smart-capture.ts` (Vercel Serverless Function เป็น proxy เก็บ `GEMINI_API_KEY` ฝั่ง server, ยืนยันตัวตนด้วย Firebase ID token ผ่าน `jose`'s `createRemoteJWKSet`/`jwtVerify` เทียบกับ Google's public JWKS โดยตรง — เลือกแทน `firebase-admin`+service-account key เพื่อเลี่ยงต้องมี secret ตัวที่สอง ตามที่ user เลือกไว้ก่อนหน้า, เรียก Gemini `gemini-2.0-flash` ผ่าน `fetch` ตรงๆ ไม่ใช้ SDK เพิ่ม, บังคับ JSON output ด้วย `generationConfig.responseMimeType`), แก้ `vercel.json` ให้ rewrite ยกเว้น `/api/*` (`/((?!api/).*)`) ไม่งั้น catch-all เดิมจะกลืน request ไปที่ Function, เพิ่ม dependency `jose` และ devDependency `@vercel/node`
- **UI wiring:** เพิ่ม `prefill?: Partial<CalendarEventInput>` ให้ `EventFormModal` (แยกจาก `initialEvent` — ยังคง `isEdit=false` และ quickCapture semantics เดิม แค่ seed ค่าเริ่มต้นของฟอร์ม), สร้าง `SmartCaptureModal` ใหม่ (gate ด้วยสถานะ sign-in, เลือกรูป → แปลง base64 → ยิง `/api/smart-capture` พร้อม ID token → ส่งผลลัพธ์กลับ), แก้ `QuickCaptureModal` ให้เมื่อเลือกประเภท "กิจกรรม" ขึ้นตัวเลือกกลาง "กรอกฟอร์มเอง" vs "สแกนจากรูปภาพ" ก่อนเสมอ — ทั้งสองทางสุดท้ายไปจบที่ `EventFormModal` เดิม (มีหรือไม่มี `prefill`) ผู้ใช้ยังต้องตรวจสอบ/แก้ไข/กด "บันทึก" เองเสมอ (ไม่ auto-submit ตาม Business Rule ของ spec), แก้ `App.tsx` ส่ง `cloudSync.user` ลงไปเป็น prop ใหม่ของ `QuickCaptureModal`
- **ยืนยันแล้ว:** `npx tsc --noEmit` และ `npm run build` ผ่านสะอาด (ไม่มี type error, chunk-size warning เดิมที่มีอยู่แล้วไม่ใช่ของใหม่); ทดสอบใน browser ผ่าน Vite dev server จริง — ตัวเลือก "กรอกฟอร์มเอง"/"สแกนจากรูปภาพ (ใหม่)" ขึ้นถูกต้องตอนเลือกประเภท "กิจกรรม" ใน Quick Capture, เส้นทาง "สแกนจากรูปภาพ" ตอนยังไม่ได้ sign in แสดงข้อความบังคับ sign in + ปุ่ม "กรอกฟอร์มเองแทน" ถูกต้อง, กดปุ่มนั้นแล้วไปเปิด `EventFormModal` โหมด quickCapture (หัวข้อ "+ Add to My Today — กิจกรรม", ฟิลด์ "ชื่อกิจกรรม *" บังคับอย่างเดียว) ได้ถูกต้อง
- **ยังไม่ได้ยืนยัน (บล็อกจากสภาพแวดล้อม ไม่ใช่บั๊กในโค้ด):** endpoint `/api/smart-capture` ตัวจริงยังทดสอบไม่ได้ เพราะ Vite dev server ไม่รัน Vercel Serverless Function ต้องใช้ `vercel dev` หรือ deploy จริงเท่านั้น — และเส้นทาง sign-in-then-scan แบบเต็ม (ต้องมี Google Sign-In จริงเหมือนที่ Sprint 12 เพิ่งพิสูจน์) ก็ยังไม่ได้ลองพร้อมกับ endpoint จริง; user ยังต้องไปสร้าง Gemini API key ที่ Google AI Studio แล้วตั้งเป็น environment variable `GEMINI_API_KEY` บน Vercel ก่อน Gate 13 จะยืนยันครบ
