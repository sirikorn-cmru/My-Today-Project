## ขอบเขตของเอกสารนี้

Smoke Test ทั้งแอป (10 หน้าจอตามตาราง "หน้าจอทั้งหมด" ใน `spec.md` ที่ root repo บวกฟีเจอร์ข้ามหน้า Quick Capture) ทดสอบกับ **local dev server** (`npm run dev` ผ่าน launch config `my-today-dev`, `http://localhost:5173`) วันที่ทดสอบ **2026-09-20** ผู้ทดสอบเข้าถึงแอปผ่านเบราว์เซอร์อัตโนมัติ (Chromium ที่ควบคุมผ่าน MCP browser tool) ทดสอบแบบ end-to-end จริงในเบราว์เซอร์ ไม่ได้อ่านโค้ดแล้วอนุมานผล

**ไม่ครอบคลุม:** ฟีเจอร์ที่ต้อง sign in จริง (Cloud Sync การ sync ข้ามอุปกรณ์จริง, Smart Capture การเรียก Gemini API จริง) — ทดสอบเฉพาะสถานะ "ยังไม่ sign in" (sign-in gate + fallback) ตามที่ระบุในโจทย์ ไม่ได้กรอกอีเมล/รหัสผ่านหรือกด sign in จริงใดๆ ทั้งสิ้น

**ข้อจำกัดสำคัญของเครื่องมือทดสอบที่พบระหว่างการทดสอบ (ไม่ใช่บั๊กของแอป แต่กระทบขอบเขตที่ทดสอบได้จริง):**
1. **Native `window.confirm()` dialog ถูกปิดใช้งานโดยเครื่องมือ browser automation เอง** — ยืนยันจาก Console warning ที่ระบบเบราว์เซอร์ส่งออกมาเองตรงๆ ว่า `"native JavaScript dialogs are disabled in this browser; confirm() returned false to the page."` ผลคือทุกครั้งที่กดปุ่ม "ลบ" (Task/Event/File/Note/Link/Life Area — ทุกจุดที่ใช้ `window.confirm()` ตาม grep source code จริง) ระบบจะได้ค่า `false` กลับไปเสมอ เท่ากับ "กดยกเลิก" อัตโนมัติ ไม่มีทางกด "ยืนยันลบ" จริงผ่านเครื่องมือนี้ได้เลย — ฝั่ง "ยกเลิกแล้วข้อมูลไม่หาย" ทดสอบได้และ **ผ่าน** ทุกจุด แต่ฝั่ง "ยืนยันแล้วข้อมูลหายจริง" **ทดสอบไม่ได้ในรอบนี้** ต้องให้คนทดสอบบนเบราว์เซอร์เดสก์ท็อปจริงเป็นผู้กดยืนยันเอง
2. **ไม่สามารถเลือกไฟล์จาก OS File Picker ผ่าน automation ได้** — `HTMLInputElement` ชนิด `file` ไม่ยอมให้ set ค่าโปรแกรมได้ (ข้อจำกัดด้านความปลอดภัยของเบราว์เซอร์เอง ยืนยันจาก error `InvalidStateError` ตรงๆ) กระทบ: (ก) ทดสอบอัปโหลดไฟล์จริงบน `/files` ไม่ได้ (ข) ทดสอบ Quick Capture ประเภทไฟล์ไม่ได้ (ค) ทดสอบกฎ Life-Area-delete-cascade เฉพาะส่วน FileRecord แบบ end-to-end ไม่ได้ (ยืนยันได้แค่ผ่าน Task/Event/Note/Link)

## สรุปปัญหาที่พบ

ไม่พบ**บั๊กของแอปพลิเคชัน**เลยตลอดการทดสอบ (ไม่มี console error จุดใดเลยทั้ง 10 หน้า, ทุก golden path และทุก required-field validation ที่ทดสอบได้ทำงานถูกต้องตามที่ออกแบบไว้, Quick Capture non-leak rule ทำงานถูกต้อง, กฎ organize-mode ที่ต้อง re-enforce validation ก็ทำงานถูกต้อง) ปัญหาที่พบทั้งหมดเป็น**ข้อจำกัดของเครื่องมือทดสอบ** ไม่ใช่ของแอป ดังนี้:

1. **[ปิดแล้ว 2026-09-21] Native `window.confirm()` ถูกปิดใช้งานโดย browser automation tool** — ในรอบแรกทำให้กด "ยืนยันลบ" ไม่สำเร็จเลย กระทบ **TC-25 (กฎห้าม cascade delete ของ Life Area)** โดยตรง — **ปิดประเด็นแล้วในรอบตรวจซ้ำ 2026-09-21** โดย stub `window.confirm` ให้คืนค่า `true` (จำลองผู้ใช้กด OK) แล้วกดปุ่ม "ลบ" ผ่าน UI จริง ผลคือกฎนี้ **ผ่าน** (ดูภาคผนวก) หมายเหตุ: สิ่งที่ถูกจำลองคือ *ตัว dialog ของเบราว์เซอร์* เท่านั้น ไม่ใช่โค้ดของแอป — ตรรกะการลบและการเคลียร์ `lifeAreaId` เป็นของแอปจริงทั้งหมด
2. **[ปิดแล้ว 2026-09-21] เลือกไฟล์จาก OS File Picker ผ่าน automation ไม่ได้** — กระทบ TC-14 และ TC-37 — **ปิดประเด็นแล้วในรอบตรวจซ้ำ 2026-09-21** โดยสร้าง `File` object แล้วใส่เข้า `input[type=file]` ผ่าน `DataTransfer` และ dispatch event `change` จริง (ตัว handler ของแอปทำงานเองทั้งหมด — พิสูจน์ได้จากการที่แอปเติมชื่อไฟล์ให้อัตโนมัติ) ผลคือทั้งสองเคส **ผ่าน** (ดูภาคผนวก)
3. **[Observation ไม่ใช่บั๊ก]** พบ Task ชื่อ "SPRINT15-LOCATION-TEST" ค้างอยู่ใน LocalStorage ของ dev server ตั้งแต่ก่อนเริ่มทดสอบรอบนี้ (น่าจะเป็นข้อมูลทดสอบค้างจาก Sprint 15) ไม่กระทบผลการทดสอบใดๆ แต่ควรพิจารณาล้าง LocalStorage/reseed ก่อนการสาธิตจริงหากไม่ต้องการให้ปรากฏ
