# Competition Demo Script — My Today

เชื่อมโยงกลับ: [[index|01-prototypes]], [[user-journey-student|User Journey: นักศึกษา]], [[user-journey-general-person|User Journey: บุคคลทั่วไป]], [[../../01-requirements/01-spec/20260806-012-my-today-sprint11-competition-demo-freeze|Sprint 11]]

## ขอบเขตของเอกสารนี้

เอกสารนี้เป็น **สคริปต์สำหรับ demo การแข่งขันจริง** ตาม Sprint 11 Business Rule ข้อ 2 (Final Competition User Journey) และข้อ 3 (Positioning Narrative) — ไม่ใช่เอกสาร requirement/design เชิงแนวคิด แต่เป็นลำดับขั้นตอนที่ผู้นำเสนอใช้พูด+คลิกจริงบนแอปที่ deploy อยู่ ทุกขั้นตอนอ้างอิงป้ายข้อความ (label) จริงในแอป ณ วันที่เขียนเอกสารนี้ (20260825) ไม่ใช่การเดา

**สถานะความพร้อม:** Sprint 1-10 ทั้งหมด build เสร็จแล้ว (ดู [[../../01-requirements/backlog|backlog.md]]) ทำให้ Final Competition User Journey ทั้งสอง persona ด้านล่างนี้**ทำได้จริงในแอปตอนนี้ทุกขั้นตอน** — Sprint 11 เองยังอยู่ระหว่างทำ ("กำลังดำเนินการ": เหลือ Browser Compatibility Matrix การรันทดสอบจริง, Black Box Testing เป็นทางการ, Gate 11) แต่สิ่งที่เหลือเป็นงาน polish/testing ไม่ใช่ฟีเจอร์ที่ demo scenario ต้องพึ่งพา จึงไม่บล็อกการซ้อม/ใช้สคริปต์นี้

## 1. เปิดการนำเสนอ — Positioning Narrative (Business Rule ข้อ 3)

**ห้ามพูดว่า** "เราพัฒนาเว็บแอปสำหรับจัดการ Task" (จะถูกเทียบกับ Todoist/Notion/Google Calendar ทันที)

**ให้พูดตามลำดับนี้:**

1. _"ปัญหาไม่ใช่คนไม่มีแอป แต่คนมีแอปมากเกินไป ข้อมูลที่ต้องใช้ในชีวิตจึงกระจัดกระจายอยู่คนละที่"_
2. _"My Today เป็น Personal Daily Workspace ที่จัดข้อมูลตามชีวิตของคน ไม่ได้จัดตามระบบที่องค์กรสร้างขึ้น"_

จากนั้นเข้าสู่ demo ทั้งสอง persona ด้านล่าง — **ใช้ Core เดียวกันทั้งหมดไม่มี code path แยกตาม persona** (ย้ำประเด็นนี้ระหว่าง demo ได้ เป็นหลักฐานว่า "One Life, One Workspace" ไม่ใช่แค่คำโฆษณา)

## 2. Demo ที่ 1 — persona นักศึกษา (Task "ส่งรายงาน HCI", Life Area "Study")

อ้างอิง [[user-journey-student|User Journey: นักศึกษา]] ทุกขั้นตอน — คลิกจริงตามลำดับนี้:

| # | การกระทำจริงบนแอป | สิ่งที่ควรพูด |
|---|---|---|
| 1 | กดปุ่มลอย **"⚡ Add to My Today"** (มุมล่างซ้ายของทุกหน้า) → เลือก **"งาน (Task)"** → พิมพ์แค่ชื่องาน "ส่งรายงาน HCI" → บันทึก | "แค่นึกออกก็บันทึกได้ทันที ไม่ต้องกรอกฟอร์มเต็มตอนนี้" |
| 2 | ไปแท็บ **Inbox** ที่ NavBar ด้านล่าง → เห็นงานอยู่ใน **"My Inbox"** (แท็บ "Inbox (N)") | "ทุกอย่างที่จับได้เร็วๆ จะมารวมกันที่ Inbox ก่อน ยังไม่ตัดสินใจอะไรตอนนั้น" |
| 3 | กด **"จัดเข้า Life Area"** บนรายการ → เลือก Life Area **"Study"** → กำหนดวันที่/เวลา deadline → บันทึก | "ตอนนี้ค่อยจัดว่ามันอยู่ในส่วนไหนของชีวิต — Study, Work, Finance, อะไรก็ตามที่เป็นจริงของแต่ละคน" |
| 4 | เปิด Task นั้นจาก หน้า **งานทั้งหมด** (`/tasks`) → กด **"รายละเอียด"** → หน้า **Task Detail** เปิดขึ้น แสดง **What / When / Information** ในหน้าเดียว → ใน Information แนบไฟล์ที่มีอยู่ (เลือกจาก dropdown "+ แนบไฟล์ที่มีอยู่...") | "นี่คือจุดต่างจาก to-do app ทั่วไป — งานหนึ่งชิ้นไม่ใช่แค่ชื่อ แต่รวมทั้งว่าต้องทำอะไร เมื่อไร และต้องใช้อะไรบ้าง อยู่หน้าเดียวจบ" |
| 5 | ในหน้า Task Detail เดียวกัน ตั้ง **Reminder** เป็น "ก่อน 1 วัน" จาก dropdown | "ไม่ต้องพึ่งค่าเตือนกลางของระบบเสมอไป ตั้งเองได้เป็นรายชิ้น" |
| 6 | ไปหน้า **ปฏิทิน** (`/calendar`) → เห็น deadline ของงานนี้ปรากฏในมุมมองวันนี้อัตโนมัติ (ไม่ต้องสร้างซ้ำ) | "Deadline ของงานโผล่ในปฏิทินเองโดยไม่ต้องพิมพ์ซ้ำสองที่" |
| 7 | ไปหน้า **Timeline** (`/timeline`) → เห็นงานอยู่ในกลุ่ม **"ถัดไป (Next)"** หรือ **"ตอนนี้ (Now)"** ตามเวลาจริง | "แทนที่จะเปิดปฏิทินทั้งเดือน ถามแอปตรงๆ ว่า 'ตอนนี้ต้องทำอะไรก่อน' แอปตอบให้เลย" |
| 8 | กลับหน้า **วันนี้** (Dashboard) → เห็นงานอยู่ใน "งานของวันนี้" เรียงลำดับอัตโนมัติ | "จัดลำดับให้อัตโนมัติด้วยกฎตายตัว ไม่ใช่ AI เดา — เกินกำหนดมาก่อนเสมอ" |
| 9 | กดสถานะงานเป็น **"Done"** จาก dropdown สถานะบน card | "ทำเสร็จ กดจบตรงนั้นเลย" |
| 10 | ชี้ที่ส่วน **"ความคืบหน้าวันนี้"** บน Dashboard → ตัวเลข "วันนี้เสร็จแล้ว X จาก Y เรื่อง" และแยกตาม Life Area "Study" อัปเดตทันที | "เห็นความคืบหน้าของวันแบบไม่ตัดสิน ไม่มีคำว่า Score ไม่มีการเปรียบเทียบกับใคร" |

## 3. Demo ที่ 2 — persona บุคคลทั่วไป (Task "จ่ายค่าไฟ", Life Area "Finance")

อ้างอิง [[user-journey-general-person|User Journey: บุคคลทั่วไป]] — **ย้ำกับกรรมการว่านี่คือแอปตัวเดียวกัน ปุ่มเดียวกัน หน้าเดียวกันกับ demo ที่ 1 ทุกจุด** ไม่มีโหมด/เมนูแยกสำหรับ "บุคคลทั่วไป":

| # | การกระทำจริงบนแอป | สิ่งที่ควรพูด |
|---|---|---|
| 1 | กด **"⚡ Add to My Today"** → เลือก **"งาน (Task)"** → พิมพ์ "จ่ายค่าไฟ" → บันทึก | "คนละบริบทชีวิตเลย จากงานเรียนเป็นเรื่องบ้าน แต่ใช้ทางเข้าเดียวกันเป๊ะ" |
| 2 | ไปแท็บ **Inbox** → กด **"จัดเข้า Life Area"** → เลือก **"Finance"** → กำหนด deadline ก่อนสิ้นเดือน | "Life Area ไม่ใช่แค่ 'วิชาเรียน' อีกต่อไป — มันคือบริบทชีวิตจริงของแต่ละคน" |
| 3 | เปิด Task Detail → แนบไฟล์ใบแจ้งหนี้ค่าไฟใน Information | "ใบแจ้งหนี้อยู่ติดกับงานเลย ไม่ต้องไปหาในโฟลเดอร์อื่น" |
| 4 | ไปหน้า **Timeline** → เห็น "จ่ายค่าไฟ" ปรากฏในกลุ่มที่เหมาะสมของวันนี้ (ถ้ากำหนดวันนี้) | — |
| 5 | รอ/แสดง **การแจ้งเตือน** (แท็บแจ้งเตือน หรือ notification banner บน Dashboard) เมื่อใกล้ครบกำหนด | "ระบบเตือนตามกำหนดจริง ไม่ต้องจำเอง" |
| 6 | กดสถานะเป็น **"Done"** | "จ่ายเสร็จ ปิดงาน" |
| 7 | ชี้ **"ความคืบหน้าวันนี้"** บน Dashboard → เห็นตัวเลขแยกของ Life Area "Finance" เพิ่มขึ้นแยกจาก "Study" ของ persona ก่อนหน้า (ถ้ายังมีข้อมูลค้างจาก demo ที่ 1 ในวันเดียวกัน) | "งานจากหลายด้านของชีวิตอยู่ในที่เดียว แต่ยังแยกดูเป็นส่วนๆ ได้เมื่อต้องการ" |

## 4. ปิดการนำเสนอ — Positioning Narrative (ต่อ)

_"ทุกวันนี้เราไม่ได้ขาดระบบ แต่ชีวิตของเรากระจัดกระจายอยู่ในหลายระบบ My Today จึงไม่ได้สร้างอีกระบบหนึ่งขึ้นมาเพิ่ม แต่สร้างพื้นที่ที่เริ่มจากชีวิตของคน และตอบคำถามง่ายที่สุดว่า วันนี้ฉันต้องทำอะไร"_

## 5. เตรียมตัวก่อน Demo จริง (Checklist)

- [ ] เปิดแอปในเบราว์เซอร์ที่ล้าง LocalStorage/IndexedDB มาก่อน หรือรู้ว่า seed data ปัจจุบันมีอะไรอยู่แล้ว (ดู `src/data/seedTasks.ts`/`seedEvents.ts`/`seedFiles.ts`) เพื่อไม่ให้ demo สับสนกับข้อมูลทดสอบเก่า
- [ ] เตรียมไฟล์ตัวอย่างสั้นๆ ไว้ล่วงหน้าสำหรับขั้นตอน "แนบไฟล์" ทั้งสอง persona (เอกสารสั้นๆ พอสาธิตได้ ไม่ต้องเป็นไฟล์จริง)
- [ ] เปิด DevTools Console ไว้เบื้องหลัง (ไม่ต้องโชว์กรรมการ) เผื่อเกิด error ระหว่าง demo จะได้รู้ทันที
- [ ] ซ้อมพูด Positioning Narrative ให้ลื่น **ห้ามอ่านจากสคริปต์ตรงๆ หน้ากรรมการ**
- [ ] ทดสอบ flow เต็มทั้งสอง persona อย่างน้อย 1 รอบก่อนวัน demo จริง
