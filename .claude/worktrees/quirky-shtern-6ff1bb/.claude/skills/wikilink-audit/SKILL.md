Skill นี้ตรวจสอบทั้ง `.docs/` Obsidian vault ของโปรเจกต์ "My Today Project" ว่ามี `[[wikilink]]` ที่ชี้ไปยังไฟล์ที่ไม่มีอยู่จริงหรือไม่ ครอบคลุมทุกไฟล์ `.md` ในทุกโฟลเดอร์ย่อย (`01-requirements/` ทั้ง `01-spec/` และ `backlog.md`, `00-archived/`, `05-log/`, `02-design/` ถึง `04-retrospectives/`, ทุก `index.md`) ไม่ใช่แค่เทียบ `backlog.md` กับ `01-spec/` แบบที่ `backlog-sync-check` ทำ

## 1. เรียก subagent `wikilink-auditor` ให้ตรวจสอบและแก้ไข

เรียก Agent tool โดยใช้ `subagent_type: "wikilink-auditor"` พร้อมส่งวันที่ปัจจุบันในรูปแบบ `YYYYMMDD` (ดึงจาก currentDate ใน system context ของบทสนทนานี้ — ห้ามให้ subagent คำนวณเอง) subagent นี้จะ:

- สแกนทุกไฟล์ `.md` ใต้ `.docs/` และไล่ดึง wikilink ทุกอันออกมา
- resolve แต่ละ wikilink ตาม convention ของ vault นี้ (path relative กับโฟลเดอร์ของไฟล์ที่ลิงก์ออกไป ไม่ใช่ relative กับ vault root) แล้วเช็คว่าไฟล์ปลายทางมีอยู่จริงหรือไม่
- แก้ไขให้อัตโนมัติเฉพาะกรณีที่หา candidate ได้แบบไม่กำกวม (เจอไฟล์ที่ตรงกันแค่ไฟล์เดียว) เช่น ไฟล์ถูกย้ายโฟลเดอร์ หรือถูกเปลี่ยนชื่อ slug แต่ยังใช้ `{YYYYMMDD}-{RUNNING_NO}` เดิม
- ถ้ากรณีไหนกำกวม (ไม่พบ candidate เลย หรือพบมากกว่า 1) จะไม่แก้ให้ — รายงานกลับมาเฉยๆ ให้ user ตัดสินใจเอง
- บันทึก log เฉพาะกรณีที่มีการแก้ไขจริง ถ้าไม่พบ broken link เลย หรือพบแต่แก้ไม่ได้เพราะกำกวม จะไม่เพิ่ม log

## 2. รายงานผลให้ user

สรุปผลจาก subagent ให้ user ทราบ:

- จำนวนไฟล์ที่สแกนและจำนวน wikilink ที่ตรวจสอบทั้งหมด
- ถ้าไม่พบ broken link เลย บอกตรงๆ ว่าไม่มีอะไรต้องแก้
- ถ้ามีลิงก์ที่แก้ไขให้อัตโนมัติแล้ว บอกว่าแก้อะไรไปบ้าง จากไฟล์ไหนไปไฟล์ไหน และเพราะอะไร (moved-file หรือ renamed-slug)
- ถ้ามีลิงก์ที่ยังเสียอยู่และกำกวม (ไม่มี candidate ชัดเจน หรือมีหลาย candidate) ให้แจ้ง user พร้อมตัวเลือกที่เจอ เพื่อให้ user ตัดสินใจว่าจะแก้เป็นอะไร — ถ้า user เลือกแล้วให้แก้ตามนั้นได้เลยโดยไม่ต้องเรียก subagent ใหม่

ไม่ต้อง push ขึ้น GitHub เองโดยอัตโนมัติ — ถามยืนยันกับ user ก่อนเสมอ ตาม convention ที่กำหนดไว้ใน `CLAUDE.md`
